# Peek 1.5.0

Peek 1.5.0 is the first signed, non-debuggable release. It focuses on private-content safety, offline reliability and the surfaces that make local data visible and controllable.

## Highlights

- **Security center** — session state, cookie names (never values), on-device sizes, network destinations, recent outcomes and one-tap private wipe or sign-out.
- **Private vault manager** — per-profile sealed sizes, open/seal/delete actions, and passphrase-encrypted export/import of the private vault.
- **Biometric-bound vault** — the vault data key now lives in Android Keystore with a five-minute user-authentication window and is invalidated when biometrics are re-enrolled. Legacy vault files still open through a migration fallback.
- **Field-level metadata encryption** — captions, profile text, media URLs, location, audio and local file paths are AES-GCM encrypted at rest. Older plaintext rows are re-sealed on their next write.
- **Private auto-lock** — private content re-hides after 1, 2, 5 or 15 minutes, or never, configurable in Settings.
- **Private feed upgrades** — search, media-type filters, sorting, circles, “new since last visit”, multi-select downloads and collections.
- **Stories and comment threads** — the authenticated story tray now opens a full pager with progress and seen marks; comments support read-only replies and local caching with refresh-on-open.
- **Accent improvements** — hue, saturation, brightness, hex input, and copy/paste theme tokens.
- **Localisation** — English, Hindi, Spanish, Portuguese, Arabic and Japanese for navigation, settings, security, vault and private-feed surfaces, with RTL support.
- **Performance** — new database indices, configurable image-cache limit, and pagination/caching fixes.
- **Encrypted private backup v2** — private metadata and sealed vault files under a separate passphrase.

## Security notes

- No analytics, crash reporting, Peek server or tracking.
- Android cloud/adb backup remains disabled.
- Private media never goes to the public gallery.
- Release builds are signed with a key stored outside the repository, are non-debuggable and R8-minified.
- The keystore and its password file are never committed or attached to a release.

## Upgrading from a debug build

Debug APKs up to v1.4.0 were signed with the standard Android debug key. Android will refuse to install a release-signed APK over them because the signatures differ. Uninstall the debug build first; local follows, downloads and settings will be removed with it. Release builds from v1.5.0 onward can update each other in place.

## Verify the download

```powershell
Get-FileHash .\peek-1.5.0-release.apk -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

The two hashes must match.

## Known limitations

- Instagram does not expose comment text to guests; comments require an optional signed-in session.
- Full-screen copy outside the localised surfaces remains English.
- Private media availability still depends on what Instagram exposes to your own session.
