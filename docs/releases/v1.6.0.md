# Peek 1.6.0

Peek 1.6.0 is the release that turns the 1.5.0 hardening into something buildable and testable: a real CI gate, reproducible dependency checks, an instrumented suite that actually runs on Android 17, and a set of feed, vault and settings improvements on top.

## Highlights

- **Android Lint is now a CI gate** — lint errors fail the build, and the findings from that first pass were fixed rather than suppressed.
- **Dependency verification** — Gradle verification metadata covers the build, and a scheduled workflow re-verifies it, so a swapped or tampered artifact breaks the build instead of shipping.
- **Signed releases from a tag** — pushing `v*` builds the release APK, verifies the signature and the non-debuggable flag, and publishes the APK with `SHA256SUMS.txt` and these notes.
- **Instrumented suite runs on Android 17 again** — the harness was broken, not the app: Espresso was pinned to 3.7.0 (`InputManager.getInstance()` was removed in Android 16/17, which killed every Compose test inside `onIdle`), the `runBlocking` tests were declared as returning `Unit`, and the migration fixture gained the missing `searches` table. Device result: **18/18, twice back-to-back on one install**.
- **Feed performance** — decrypted metadata and Keystore handles are cached and the cache is cleared on lock, query indices added with a 5→6 Room migration, next-page covers prefetched, Coil memory cache capped, players paused when the app leaves the foreground, and a 10k-post query-plan stress test guards the indices.
- **Post notes** — per-post private notes stored in the encrypted library DataStore, searchable offline and shown in the post viewer.
- **Calm mode** — an optional quieter feed presentation for when you do not want to be sold to.
- **Vault and timeline** — vault search and sort, a request timeline in the security surfaces, and launcher shortcuts for the security center and the private feed.
- **Settings search** — settings rows filter by title or subtitle.
- **Screenshot protection on private profiles** — `FLAG_SECURE` extended to the private profile screens, verified on device by an A/B on the same activity window.
- **Metadata key rotation** — versioned ciphertexts (`enc:vN:`) with a rotation path exposed in the Security Center.
- **Docs** — `SECURITY.md`, `TESTING.md`, `DEPENDENCIES.md`, `RELEASE_SIGNING.md` and `FDROID.md`, plus an `AGENTS.md` brief that carries the operating lessons.

## Security notes

- No analytics, no crash reporting, no Peek server, no tracking.
- Android cloud/adb backup stays disabled.
- Private media never goes to the public gallery; `FLAG_SECURE` covers the private profile and session surfaces.
- Sensitive clipboard text is cleared 60 seconds after it is copied.
- Release builds are R8-minified, non-debuggable, and signed with a key that is stored outside the repository and supplied to CI as a secret.

## Verification status

Device-verified on a Galaxy S26 (SM-S942B, Android 17): biometric vault unlock, `FLAG_SECURE` capture blocking, and the 60-second clipboard clear. The remaining manual items — vault sealing of real files, auto-lock re-hiding, panic mode, shake-to-hide, enrollment invalidation and queue restore after a process kill — need a signed-in Instagram session or a non-empty vault, and are **not verified in this release**. The Instagram login on the test device was deliberately not performed, so no session cookie was placed on it.

## Upgrading

Release builds from v1.5.0 onward update each other in place. Debug APKs from v1.4.0 or earlier are signed with the debug key and must be uninstalled first.

## Verify the download

```powershell
Get-FileHash .\peek-1.6.0-release.apk -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

The two hashes must match.

## Known limitations

- Instagram does not expose comment text to guests; comments need an optional signed-in session.
- Private-content behaviours listed above are covered by tests and code review but were not exercised on a real vault in this release.
- Full-screen copy outside the localised surfaces remains English.
- Private media availability still depends on what Instagram exposes to your own session.
